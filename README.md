# Personal Portfolio — Flutter Web + Firebase

A responsive single-page developer portfolio built with **Flutter Web** and a
hidden **admin panel** backed by **Firebase** (Auth / Firestore / Storage).
Content is edited at runtime through `/admin` — no redeploy needed.

| | |
|---|---|
| State management | `flutter_bloc` (Cubits) |
| Architecture | Feature-first Clean Architecture (`data` / `domain` / `presentation`) |
| DI | `get_it` |
| Routing | `go_router` with an authenticated `/admin` guard |
| Animations | `flutter_animate`, custom scroll-reveal engine, animated navbar/theme toggle |

## Project structure

```
lib/
  core/                     theme, router+guard, DI, constants, errors, utils
  features/
    portfolio/              public site
      data/                 models, Firestore datasources, repository impls
      domain/               entities (Profile, Project) + repository interfaces
      presentation/         cubit, page, section widgets
    admin/
      auth/                 login feature (cubit + page)
      media/                Storage upload/delete repository
      profile_management/   profile editor + live preview
      project_management/   project list (reorder) + create/edit form
      presentation/         dashboard + shared AdminShell
  firebase_options.dart     generated by flutterfire configure
  main.dart
```

All Firestore/Storage access goes through the repository layer — the UI never
touches Firebase directly. Every async action surfaces loading / success /
error states via Cubits.

## Setup

### 1. Prerequisites

- Flutter (stable channel) with web enabled: `flutter devices` should list Chrome
- Node.js ≥ 18 (for the admin-claim script)
- [Firebase CLI](https://firebase.google.com/docs/cli): `npm i -g firebase-tools`

### 2. Install dependencies

```bash
flutter pub get
```

### 3. Create a Firebase project & connect it

1. Create a project at <https://console.firebase.google.com> (Analytics optional).
2. Enable **Authentication → Sign-in method → Email/Password**.
3. Enable **Firestore Database** (production mode).
4. Enable **Storage**.
5. Generate Flutter config:

```bash
dart pub global activate flutterfire_cli
flutterfire configure
# select your project, platforms: web
```

This writes `lib/firebase_options.dart`. Until then the app still runs in a
UI-only mode (Firebase calls fail gracefully with error states).

### 4. Seed the admin user (no public sign-up exists)

```bash
# Create the user first: Firebase Console › Authentication › Users › Add user
npm install firebase-admin --no-save

# Authenticate the CLI tooling (either one):
gcloud auth application-default login
# …or set GOOGLE_APPLICATION_CREDENTIALS=/path/to/service-account-key.json

ADMIN_EMAIL=you@example.com node scripts/set-admin-claim.mjs
```

The script sets the custom claim `admin: true`, which both
`firestore.rules` and `storage.rules` require for write access.
The user must sign out/in once for the claim to take effect.

### 5. Deploy security rules

```bash
firebase use --add            # link the project (first time only)
firebase deploy --only firestore:rules,storage:rules
```

Rules summary:
- `profile/**`, `projects/**`, and used Storage paths: **public read**, **admin-only write**
- Admin = signed-in account with the `admin == true` custom claim
- All other documents/objects are denied

### 6. Run locally

```bash
flutter run -d chrome
```

Public site: `http://localhost:…/#/` · Admin: click the discreet “Admin” link
in the footer or open `/admin/login` directly.

## Deploy to Firebase Hosting

```bash
flutter build web --release
firebase deploy --only hosting
```

`firebase.json` serves `build/web`, rewrites all routes to `/index.html`
(SPA), and sets long-lived immutable caching for `/assets/**` while keeping
the bootstrap files fresh.

Optional CI-friendly one-liner:

```bash
flutter build web --release && firebase deploy --only hosting,firestore:rules,storage:rules
```

## Editing content (after deployment)

Sign in at `/admin/login`:

- **Profile** — name, title, tagline, bio, years of experience, availability,
  skills (name + level), social links, profile photo, PDF resume. A live
  preview mirrors the public hero while you type. Press **Save changes**.
- **Projects** — create/edit/delete, mark as *featured*, drag rows to reorder
  (order applies to the public site instantly). The first screenshot becomes
  the card cover.

Changes appear on the public site immediately (fresh fetch per visit).

## Troubleshooting

| Symptom | Fix |
|---|---|
| `UnsupportedError: firebase_options.dart has not been generated` | Run `flutterfire configure` (step 3). |
| Login says “Invalid email or password” | Check the user exists; claims aren’t needed for sign-in itself. |
| Writes fail with permission-denied | The `admin` claim is missing/expired — rerun step 4 and sign out/in. |
| Uploads fail but Firestore works | Redeploy storage rules; check you’re on the right bucket/project. |
